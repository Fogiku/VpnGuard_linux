# Совместная работа над VpnGuard Linux

Рабочая ветка продукта — `main`. Ветка `releases` содержит опубликованные сборки. Перед выбором задачи прочитайте [программу развития](PLATFORM_INTEGRATION_READINESS.md) и [изменения после аудита](CHANGELOG.md).

## Как взять задачу

1. Обновите сведения о ветках (`git fetch origin`). Проверьте открытые Issues и PR, недавние коммиты, `git worktree list` и `git status -sb` в своём checkout. Один каталог с незакоммиченными правками может использоваться другим исполнителем.
2. Ищите по результату задачи и затрагиваемому компоненту. Сверьте найденное с исходниками и тестами текущей ветки. Пункты «осталось» в исторических планах могли быть выполнены позднее.
3. Используйте одну общую задачу для одного результата. При наличии доступа на запись зафиксируйте в общей задаче исполнителя, ветку, область файлов и критерий готовности. При пересечении продолжите существующую работу по договорённости с владельцем. Если занятость видна только в отдельном чате, укажите это при передаче.
4. Для независимой работы используйте отдельную ветку и checkout. Перед объединением повторно сверьте область изменений с обновлённой основной веткой и открытыми PR.
5. При передаче укажите коммит, полученный результат, выполненные проверки и оставшийся вопрос. Для сетевых изменений укажите отдельно, где проходила проверка — симулятор, изолированное ядро Linux или физический шлюз.
